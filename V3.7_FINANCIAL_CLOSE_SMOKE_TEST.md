# V3.7 Financial Close Foundation Smoke Test

## Itemized invoice lifecycle

1. Open **Finance & Ledger** for a delivered load with a signed POD.
2. Select **Prepare invoice draft** and confirm the base transportation line and only approved accessorials appear.
3. Confirm the total equals the displayed line items and the terms/due date match the load.
4. Select **Finalize invoice**, cancel once, and verify the invoice remains a draft.
5. Finalize again and confirm. Change the load customer or rate; the finalized invoice must retain its saved customer, terms, and line values.
6. Select **View / Print itemized invoice** and confirm the printed invoice uses the frozen snapshot.

Use two different saved loads. Give them visibly different invoice amounts, payments, and expenses.

1. Open **Finance & Ledger** for the first load.
2. Confirm the V3.7 reconciliation names that Load ID and matches only its invoice, payments, receivable, expenses, and profit.
3. Confirm journal debits equal journal credits.
4. Open **V3.7 Test Gate** and confirm the V3.7 Financial Close Gate is present.
5. Switch to the second load and change or add a payment.
6. Return to the first load and confirm none of its V3.7 values changed.
7. Confirm overpayment is shown as a negative receivable instead of being hidden as zero.

Foundation acceptance requires:

- JavaScript syntax checks pass.
- The deterministic two-load isolation assertion passes.
- Existing V3.6 actual-trip and test-gate behavior remains available.
- No button finalizes, posts, reverses, or closes financial data yet; those protected actions belong to later V3.7 milestones.
