# V3.8 Operational Integrity

## Release outcome

For one immutable Load ID, Family Legacy Commercial Command must prove that the assigned driver, truck, and trailer are eligible for the load; the cargo fits verified vehicle/equipment limits; and all required compliance/document evidence for the selected transportation type is present before dispatch and final operational completion.

V3.8 must preserve the small-fleet workflow: saved information is reused automatically, while exceptions and protected changes remain visible and auditable.

## Delivery milestones

### 1. Assignment integrity

- Reuse verified driver/truck/trailer master records and My Regular Rig.
- Add an explicit Load & Assignment reason for assignment/change/cancellation actions.
- Preserve the assignment snapshot by Load ID.
- Require reason + audit event for protected assignment changes.
- Prevent planned, expired, cancelled, or incomplete records from being treated as dispatch-ready.

### 2. Weight and equipment fit gate

- Auto-populate verified truck/trailer ratings and scale data into the load evaluation.
- Check cargo weight/dimensions and relevant payload, axle, tire, hitch/coupler, GVWR/GCWR, deck/equipment limits.
- Produce explicit PASS / REVIEW / DO NOT DISPATCH reasons.
- Keep the exact source ratings and load inputs in the operational snapshot.

### 3. Transportation-type compliance gate

- Define required checks/evidence by operation classification and transportation type.
- Block dispatch when a required driver, vehicle, authority, insurance, equipment, or document requirement is not verified.
- Do not force irrelevant compliance fields onto operation types that do not require them.

### 4. Pickup / delivery document integrity

- Tie pickup/delivery evidence, signatures, photographs, BOL/POD, and document classifications to the Load ID.
- Block workflow completion when required evidence is missing.
- Prepare document metadata for V4.0 persistent object storage and hashing.

### 5. Auto-populate and small-fleet acceptance

- Audit every main view for duplicate data entry.
- Confirm saved Business, Fleet, Load, Pickup, Delivery, Actual Trip, and Finance values flow downstream correctly.
- Verify the normal owner-operator / 1–3 driver path stays fast and does not require enterprise-only fields.
- Add a V3.8 Operational Integrity Test Gate and preserve V3.5, V3.6, and V3.7 regression gates.

## Acceptance rule

V3.8 passes only when a representative load can move from accepted estimate to verified assignment, equipment/weight approval, compliant pickup, delivery evidence, and operational completion without bypassing a failed safety/compliance condition and without re-entering information FLT already knows.

## Deferred to V4.0

Authentication, roles, multi-tenant database persistence, durable object storage, server-side audit log, backups, offline synchronization/conflict handling, and persistent document hashes remain Production Foundation work.

See `FLT_CARRY_FORWARD_REQUIREMENTS.md` for earlier requirements that must remain tracked while V3.8 is built.
